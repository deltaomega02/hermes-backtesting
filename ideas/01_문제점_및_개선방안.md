## 확인된 문제점

### 1. 3년 백테스트 -97.5% (서버비 포함)

원인:
- 2023년 저변동성 (ATR 0.745%, 역대 최저)
- SL이 ATR 기반이라 저변동성 시 너무 타이트 → 허위 손절 반복
- LONG 승률 28.7% (3년 누적 -$209)
- 서버비 3년 $362가 소자본에서 치명적

15개월 (2024-2025)만 보면 서버비 포함 +$196 (+30.6%)
→ 시장 환경에 따라 성과 극단적 차이

### 2. LONG 전략 구조적 약점

3년 데이터:
- LONG: 853거래, 승률 28.7%, PnL -$209
- SHORT: 908거래, 승률 31.8%, PnL +$77

상승장에서 풀백이 짧아 SL이 자주 터짐.
하락장 SHORT은 안정적으로 수익.

### 3. 횡보 전략 (RANGE_REVERSION) 실패

백테스트 3년: 모든 임계값에서 -88% ~ -93% (파산)
실전: 4회 발동, 전부 횡보 시 바닥잡기 LONG → 손절
현재 비활성화 완료.

### 4. 서버비 비중

$261 시드: 서버비 월 5.8% (거래 수익을 초과)
$640 시드: 서버비 월 2.4% (감당 가능)
$1000 시드: 서버비 월 1.5% (이상적)

## 개선 아이디어 (미구현, 데이터 수집 후 검토)

### 아이디어 1: 자동 방어 모드

조건: 최근 20거래 승률 25% 이하 (5승 15패)
동작: 자동으로 신규 거래 중단, 텔레그램 알림
해제: ADX 30+ 확인 시 거래 재개
목적: 2023년 같은 저변동성 구간에서 손실 방지

구현 위치: main.py의 _check_signals에 승률 체크 추가
필요 데이터: 최근 20거래 결과 (DB에서 조회)

상태: 추세 전략 20거래 후 기준값 설정 예정

### 아이디어 2: ATR 적응형 SL

현재: SL = ATR x 1.5 (고정 배수)
문제: ATR이 낮으면 SL이 타이트 → 허위 손절
개선: ATR < 0.8% 이면 SL 배수를 2.0으로 자동 조정
주의: R:R이 변하므로 손익분기 승률도 변함
상태: Optuna 50거래 후 자동 탐색 대상으로 검토

### 아이디어 3: SHORT만 모드 (하락장 특화)

15개월 백테스트:
- SHORT만: +91%, DD 27%
- 양방향: +81%, DD 54%

하락장에서는 SHORT만이 수익 높고 드로다운 낮음.
상승장에서는 거래 0 (기회 손실).

구현: 수동 전환 또는 시장 상태 기반 자동 전환
상태: 상승장 데이터 부족으로 보류

### 아이디어 4: 서버비 최적화

현재: GCP e2-micro 서울 $15.1/월
대안:
- GCP e2-micro us-central1: $0/월 (무료 티어, 레이턴시 +200ms)
- Contabo VPS: $4/월
- Oracle Cloud 무료: $0/월 (불안정할 수 있음)

1H 시스템이라 레이턴시 200ms 무관.
상태: 검토 중. 서울 리전 유지 결정.

### 아이디어 5: SOL LONG 제거 (확정 대기)

백테스트 코인별:
- BTC: 안정적 수익
- ETH: 최고 수익
- SOL LONG: 75거래 승률 29% PnL -$8 (마이너스)
- SOL SHORT: 85거래 승률 35% PnL +$238 (플러스)

SOL LONG만 제거하면 SOL이 손실 코인 → 수익 코인으로 전환.
구현: signal_engine에서 SOL + LONG 조합일 때 return None
상태: BTC LONG 포지션 종료 후 다음 업데이트 시 적용 예정
